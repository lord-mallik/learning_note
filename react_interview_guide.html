JavaScript Core

Q1 What is JavaScript? Easy +

JavaScript is a lightweight, interpreted, high-level programming language primarily used to make web pages interactive. It runs in the browser (client-side) and also on servers via Node.js (server-side).

  • Dynamic – types are determined at runtime
  • Single-threaded – runs one operation at a time
  • Event-driven – reacts to user/system events
  • Prototype-based – OOP via prototypes, not classical classes
  • First-class functions – functions can be passed, returned, and assigned
JS is the only language that runs natively in every browser — making it the foundation of the web.

Q3 What is Hoisting? Easy +

Hoisting is JavaScript's default behavior of moving declarations to the top of their scope during the compilation phase, before code execution.

  • var – hoisted and initialized with undefined
  • let/const – hoisted but NOT initialized (Temporal Dead Zone)
  • function declarations – fully hoisted (both name and body)
  • function expressions – only the variable is hoisted (not the function)
console.log(a); // undefined (hoisted)
var a = 5;

console.log(b); // ❌ ReferenceError (TDZ)
let b = 5;

greet(); // "Hello!" – function fully hoisted
function greet() { console.log("Hello!"); }

sayHi(); // ❌ TypeError – only var is hoisted, not function
var sayHi = function() { console.log("Hi!"); }
Q4 Difference between == and ===? Easy +

== (Loose equality): compares values after type coercion — JS converts types before comparing.

=== (Strict equality): compares both value AND type — no coercion.

0 == ""        // true  (coercion)
0 === ""       // false (different types)
null == undefined  // true
null === undefined // false
1 == "1"        // true
1 === "1"       // false
Always prefer === — coercion rules are complex and lead to bugs.
Q5 What is Scope? Easy +

Scope determines the accessibility (visibility) of variables. JS has 4 types:

  • Global Scope – accessible everywhere
  • Function Scope – accessible only inside that function (var)
  • Block Scope – accessible inside {} (let, const)
  • Module Scope – accessible only within the module file

JS uses Lexical Scoping — a function's scope is determined by where it is written, not where it is called.

let global = "I'm global";
function outer() {
  let outerVar = "outer";
  function inner() {
    let innerVar = "inner";
    console.log(outerVar); // ✅ accessible (closure)
    console.log(global);   // ✅ accessible
  }
  console.log(innerVar); // ❌ ReferenceError
}
Q6 What is a Closure? Easy +

A closure is a function that remembers the variables from its outer scope even after the outer function has returned. Closures are created every time a function is created.

function makeCounter() {
  let count = 0;          // private variable
  return function() {
    count++;
    return count;
  };
}
const counter = makeCounter();
counter(); // 1
counter(); // 2  — count is "closed over"

Real-world use cases: Data privacy, memoization, event handlers, React's useState (internally uses closures), module pattern.

Every React hook like useState and useEffect relies on closures to remember state between renders.
Q7 What is an Arrow Function? Easy +

Arrow functions are a shorter syntax for writing functions. Key differences from regular functions:

  • No own this – inherits this from enclosing lexical scope
  • No arguments object
  • Cannot be used as constructors (no new)
  • No prototype property
// Regular function
function add(a, b) { return a + b; }

// Arrow function
const add = (a, b) => a + b;

// 'this' difference
const obj = {
  name: "React",
  regular: function() { console.log(this.name); }, // "React"
  arrow: () => { console.log(this.name); }      // undefined
};
Q8 What is Destructuring? Easy +

Destructuring is a syntax that unpacks values from arrays or properties from objects into distinct variables.

// Array destructuring
const [a, b, ...rest] = [1, 2, 3, 4];
// a=1, b=2, rest=[3,4]

// Object destructuring
const { name, age = 25 } = { name: "Alice" };
// name="Alice", age=25 (default)

// Rename while destructuring
const { name: userName } = { name: "Alice" };

// In function params (very common in React)
const UserCard = ({ name, age }) => <div>{name}</div>;
Q9 What is the Spread Operator? Easy +

The spread operator (...) expands an iterable (array, object) into individual elements.

// Arrays
const a = [1, 2]; const b = [3, 4];
const combined = [...a, ...b]; // [1,2,3,4]

// Objects (shallow merge)
const user = { name: "Alice" };
const updated = { ...user, age: 25 }; // {name:"Alice", age:25}

// React: immutable state update
setState(prev => ({ ...prev, isLoading: false }));

// Function call
Math.max(...[1, 2, 3]); // 3
Q10 What is the Rest Operator? Easy +

The rest operator (...) collects remaining elements into an array. Same syntax as spread but used in function params or destructuring.

// Function params
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4); // 10

// Destructuring
const [first, ...others] = [1, 2, 3, 4];
// first=1, others=[2,3,4]

const { a, ...remaining } = { a:1, b:2, c:3 };
// a=1, remaining={b:2, c:3}
Key difference: Spread expands → used in expressions. Rest collects → used in declarations.
Q11 What is an Execution Context? Medium +

An Execution Context is the environment in which JavaScript code is evaluated and executed. It contains:

  • Variable Environment – all variable/function declarations
  • Scope Chain – references to outer environments
  • this – value of the current context

Types:

  • Global EC – created when JS starts; one per program
  • Function EC – created every time a function is called
  • Eval EC – created inside eval()

Each EC has two phases: Creation Phase (hoisting, this binding) and Execution Phase (line-by-line execution).

Q12 What is the Call Stack? Medium +

The Call Stack is a LIFO (Last In, First Out) data structure that tracks which function is currently being executed.

  • When a function is called → its EC is pushed onto the stack
  • When a function returns → its EC is popped off the stack
  • Stack Overflow occurs when the stack exceeds its limit (infinite recursion)
function a() { b(); }
function b() { c(); }
function c() { console.log("done"); }
a();
// Stack: [global] → [a] → [a,b] → [a,b,c] → [a,b] → [a] → [global]
Q13 What is the Event Loop? Medium +

The Event Loop is the mechanism that allows JS (single-threaded) to perform non-blocking async operations.

How it works:

  1. JS executes sync code in the Call Stack
  2. Async operations (setTimeout, fetch) are handed to Web APIs
  3. When async is done, callbacks go to the Callback Queue (macrotask)
  4. Promises go to the Microtask Queue
  5. Event Loop checks: if stack is empty → run ALL microtasks → run ONE macrotask → repeat
Priority: Microtasks (Promises) always run BEFORE Macrotasks (setTimeout).
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');
// Output: 1, 4, 3, 2
Q14 What is a Callback Function? Medium +

A callback is a function passed as an argument to another function, to be executed later (after an async operation or event).

function fetchData(url, callback) {
  setTimeout(() => {
    const data = { user: "Alice" };
    callback(data);
  }, 1000);
}

fetchData("/api/user", (data) => {
  console.log(data.user);
});
Callback Hell: Deeply nested callbacks become unreadable. Solved by Promises and async/await.
Q15 What are Promises? Medium +

A Promise is an object representing the eventual completion or failure of an async operation. It has 3 states: Pending, Fulfilled, Rejected.

const promise = new Promise((resolve, reject) => {
  const success = true;
  if (success) resolve("data");
  else reject(new Error("failed"));
});

promise
  .then(data => console.log(data))
  .catch(err => console.error(err))
  .finally(() => console.log("done"));

// Parallel execution
Promise.all([fetch(url1), fetch(url2)]); // all or fail
Promise.allSettled([...]);               // all results
Promise.race([...]);                     // first to settle
Q16 Promise vs Async/Await? Medium +

Async/Await is syntactic sugar over Promises — it makes async code look synchronous and is easier to read/debug.

// Promise chaining
fetchUser()
  .then(user => fetchPosts(user.id))
  .then(posts => console.log(posts))
  .catch(err => console.error(err));

// Async/Await (same thing, cleaner)
async function load() {
  try {
    const user = await fetchUser();
    const posts = await fetchPosts(user.id);
    console.log(posts);
  } catch(err) {
    console.error(err);
  }
}

Q18 What is Debouncing? Medium +

Debouncing ensures a function is only called after a specified delay has passed since the last invocation. Useful for search inputs, resize events.

function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}

const handleSearch = debounce((query) => {
  fetchResults(query);
}, 500);

input.addEventListener('input', e => handleSearch(e.target.value));
// API called only 500ms after user stops typing
Q19 What is Throttling? Medium +

Throttling ensures a function is called at most once per specified time period, regardless of how many times it's triggered. Useful for scroll, resize events.

function throttle(fn, limit) {
  let lastCall = 0;
  return function(...args) {
    const now = Date.now();
    if (now - lastCall >= limit) {
      lastCall = now;
      return fn.apply(this, args);
    }
  };
}
// Debounce: waits for silence → search input
// Throttle: fires at intervals → scroll handler
Q20 What are Higher Order Functions? Medium +

A Higher Order Function (HOF) is a function that either takes another function as an argument or returns a function.

// Takes a function as argument
[1,2,3].map(x => x * 2);    // map is HOF
[1,2,3].filter(x => x > 1); // filter is HOF

// Returns a function
function multiplier(factor) {
  return (num) => num * factor;
}
const double = multiplier(2);
double(5); // 10

Q22 What is Currying? Medium +

Currying transforms a function with multiple arguments into a sequence of functions each taking a single argument.

// Normal function
const add = (a, b, c) => a + b + c;
add(1, 2, 3); // 6

// Curried version
const curriedAdd = a => b => c => a + b + c;
curriedAdd(1)(2)(3); // 6

// Partial application – useful!
const add5 = curriedAdd(5);
add5(2)(3); // 10

Use cases: Reusable configurations, partial application, function composition, event handlers.

Q23 What is a Prototype? Prototype Inheritance? Prototype Chain? Medium +

Prototype: Every JS object has a hidden [[Prototype]] property linking to another object from which it inherits properties/methods.

Prototype Inheritance: Objects inherit from other objects (not classes). When you access a property, JS walks up the prototype chain to find it.

Prototype Chain: The chain of linked prototypes ending at Object.prototype (which is null).

function Animal(name) { this.name = name; }
Animal.prototype.speak = function() {
  return `${this.name} makes a noise`;
};

const dog = new Animal("Rex");
dog.speak(); // "Rex makes a noise"

// Chain: dog → Animal.prototype → Object.prototype → null
Object.getPrototypeOf(dog) === Animal.prototype; // true
Q24 Explain Memory Leaks Hard +

A memory leak occurs when memory that is no longer needed is not released, causing the app to consume increasing memory over time.

Common causes in JS/React:

  • Global variables holding references
  • Forgotten timers (setInterval without cleanup)
  • Event listeners not removed
  • Closures retaining large data
  • React: setState after component unmounts
// ❌ Leak: timer runs after unmount
useEffect(() => {
  const id = setInterval(fetchData, 1000);
}, []);

// ✅ Fix: cleanup function
useEffect(() => {
  const id = setInterval(fetchData, 1000);
  return () => clearInterval(id); // cleanup!
}, []);
Q25 Shallow Copy vs Deep Copy Hard +

Shallow Copy: Copies only the first level. Nested objects still share the same reference.

Deep Copy: Copies all levels. Completely independent clone.

const obj = { a: 1, b: { c: 2 } };

// Shallow copies
const s1 = { ...obj };
const s2 = Object.assign({}, obj);
s1.b.c = 99; // obj.b.c also changes! ❌

// Deep copies
const d1 = JSON.parse(JSON.stringify(obj)); // simple, loses functions/Date
const d2 = structuredClone(obj); // modern, handles more types ✅
d1.b.c = 99; // obj.b.c unchanged ✅
Q26 Explain Call, Apply, and Bind Hard +

All three explicitly set the value of this for a function call.

Q27 Implement Polyfill for map(), filter(), reduce() Hard + 
// Polyfill: map
Array.prototype.myMap = function(callback) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    result.push(callback(this[i], i, this));
  }
  return result;
};

// Polyfill: filter
Array.prototype.myFilter = function(callback) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    if (callback(this[i], i, this)) result.push(this[i]);
  }
  return result;
};

// Polyfill: reduce
Array.prototype.myReduce = function(callback, initialValue) {
  let acc = initialValue !== undefined ? initialValue : this[0];
  let start = initialValue !== undefined ? 0 : 1;
  for (let i = start; i < this.length; i++) {
    acc = callback(acc, this[i], i, this);
  }
  return acc;
};
Q28 How does Garbage Collection work? Hard +

JS automatically frees memory no longer needed using Mark-and-Sweep algorithm:

  1. Mark phase: Start from roots (global, call stack), mark all reachable objects
  2. Sweep phase: Free all unmarked (unreachable) objects

An object becomes eligible for GC when it has no more references pointing to it.

let user = { name: "Alice" };
user = null; // original object is now unreachable → GC eligible

// Circular reference (handled by modern GC):
let a = {}; let b = {};
a.ref = b; b.ref = a;
a = null; b = null; // both collected despite circular refs

React Fundamentals

Q1 What is React? Why React? Easy +

React is an open-source JavaScript library by Meta for building fast, interactive UIs using a component-based architecture.

Why React?

  • Virtual DOM – minimizes expensive real DOM operations
  • Component-based – reusable, testable UI pieces
  • Unidirectional data flow – predictable state management
  • Huge ecosystem – Next.js, Redux, React Query, etc.
  • React Native – same concepts for mobile development
  • Strong community & job market
Q2 What is JSX? Easy +

JSX (JavaScript XML) is a syntax extension for JavaScript that lets you write HTML-like code inside JS. Babel compiles it to React.createElement() calls.

// JSX
const element = <h1 className="title">Hello, React!</h1>;

// Compiled to
const element = React.createElement('h1', { className: 'title' }, 'Hello, React!');

JSX Rules: Must return a single root element, use className not class, self-close empty tags, wrap multi-line in parentheses, JS expressions go in {}.

Q5 What is Virtual DOM? What is Real DOM? Easy +

Real DOM: The browser's actual Document Object Model. Updating it is expensive — every change triggers reflow/repaint.

Virtual DOM: A lightweight in-memory representation of the Real DOM. React's reconciliation process:

  1. State changes → new Virtual DOM tree created
  2. React diffs new vs old Virtual DOM (diffing algorithm)
  3. Only the changed nodes are updated in the Real DOM (patching)
Virtual DOM doesn't make React fast by itself — it makes DOM updates smart and minimal, avoiding unnecessary work.
Q6 Why is the key prop important? React Fragments? Synthetic Events? Easy +

key prop: Helps React identify which list items changed, added, or removed. Without it, React re-renders the entire list unnecessarily.

items.map(item => <li key={item.id}>{item.name}</li>)
Never use array index as key if the list can reorder!

React Fragments: Let you group elements without adding extra DOM nodes:

// Both are equivalent
<React.Fragment><Child1 /><Child2 /></React.Fragment>
<><Child1 /><Child2 /></>

Synthetic Events: React's cross-browser wrapper around native DOM events. Normalized to work consistently across browsers. Examples: onClick, onChange, onSubmit.

Q7 What is Reconciliation? What is the Diffing Algorithm? Medium +

Reconciliation: The process by which React updates the DOM to match the Virtual DOM after state/prop changes.

Diffing Algorithm (React's heuristics — O(n) not O(n³)):

  • Different element types → destroy old tree, build new
  • Same element type → update only changed attributes
  • Lists with keys → match by key, only update/move changed items
  • Components of the same type: re-render and diff recursively
This is why keys matter in lists — they let React reuse DOM nodes instead of recreating them.
Q8 What causes Re-renders? Medium +

A React component re-renders when:

  • State changes – setState / useState setter called
  • Props change – parent passes new props
  • Parent re-renders – child re-renders too (by default)
  • Context changes – consuming component re-renders
  • forceUpdate() – class component method
Re-renders ≠ DOM updates. React might re-render but if the output is the same, no DOM update happens (VDom diff skips it).
Q9 Controlled vs Uncontrolled Components? Medium +

Controlled: Form data is handled by React state. Single source of truth.

const [value, setValue] = useState("");
<input value={value} onChange={e => setValue(e.target.value)} />

Uncontrolled: Form data managed by DOM itself. Use useRef to access values.

const inputRef = useRef();
<input ref={inputRef} />
// Access: inputRef.current.value

Use controlled for validation, real-time feedback. Use uncontrolled for simple forms or 3rd-party DOM libs.

Q11 React.memo, Error Boundaries, Portals, HOCs, Custom Hooks? Medium +

React.memo: HOC that memoizes a component — skips re-render if props haven't changed.

const MemoComp = React.memo(({ name }) => <div>{name}</div>);
// Only re-renders if 'name' changes

Error Boundaries: Class components that catch JS errors in their child tree. No functional equivalent (use react-error-boundary lib).

Portals: Render children outside the parent DOM hierarchy (e.g., modals, tooltips).

ReactDOM.createPortal(<Modal />, document.getElementById('portal-root'))

HOCs: Function that takes a component and returns an enhanced component (e.g., withAuth(Component)).

Custom Hooks: Functions starting with use that encapsulate reusable stateful logic using built-in hooks.

Q12 React Fiber, Concurrent Rendering, Suspense, Hydration, SSR vs CSR, Server Components Hard +

React Fiber: React 16's complete rewrite of the reconciliation engine. Enables incremental rendering — breaking work into chunks, pausing, prioritizing, and resuming.

Concurrent Rendering: React can work on multiple tasks simultaneously, interrupting low-priority renders for high-priority updates (e.g., user input). Enabled by startTransition, useTransition.

Suspense: Lets components "wait" for async data before rendering. Works with lazy loading and data fetching.

<Suspense fallback={<Spinner />}>
  <LazyComponent />
</Suspense>

Hydration: Process of attaching React's event listeners to server-rendered HTML. The HTML already exists, React just "activates" it.

Server Components (RSC): React components that run only on the server. Zero JS bundle impact. Can directly access databases. Cannot use hooks or browser APIs.

React Hooks

Q1 What is useState? How does it work? Easy +

useState is a hook that lets you add state to functional components. Returns an array of [current value, setter function].

const [count, setCount] = useState(0);

// Direct update
setCount(5);

// Functional update (safe when new state depends on old)
setCount(prev => prev + 1);

// Object state
const [user, setUser] = useState({ name: "", age: 0 });
setUser(prev => ({ ...prev, name: "Alice" }));
State updates are asynchronous and batched in React 18. Don't read state immediately after setting.

Internally, useState uses a linked list of hooks tied to the component's fiber. Each render, React reads from the same position in the list — hence hooks must always be called in the same order.

Q2 What is useEffect? Dependency Array? useEffect Lifecycle? Easy +

useEffect lets you perform side effects in functional components (data fetching, subscriptions, DOM mutations).

// Runs after every render
useEffect(() => { ... });

// Runs once on mount (componentDidMount)
useEffect(() => { ... }, []);

// Runs when deps change (componentDidUpdate)
useEffect(() => { ... }, [userId]);

// Cleanup (componentWillUnmount)
useEffect(() => {
  const sub = subscribe();
  return () => sub.unsubscribe(); // runs before next effect or unmount
}, []);

useRef returns a mutable ref object whose .current property persists across renders without causing re-renders.

Two main uses:

<input ref={inputRef} />

// 2. Mutable value (like instance variable)
const timerRef = useRef(null);
timerRef.current = setInterval(...);

Hook Rules:

  • Only call hooks at the top level (not inside loops, conditions, or nested functions)
  • Only call hooks from React function components or custom hooks
Why top level? React tracks hooks by their call order. Conditional calls would break the order between renders.

Redux & State Management

Q1 What is Redux? Architecture, Core Concepts? Medium +

Redux is a predictable state container for JavaScript apps. It centralizes application state and state logic, making state changes predictable and debuggable.

Three Principles: Single source of truth, State is read-only, Changes via pure functions (reducers).

ConceptDescription
StoreSingle JS object holding all app state
ActionPlain object describing what happened: {type, payload}
ReducerPure function: (state, action) => newState
DispatchSends an action to the store
SelectorFunction to extract specific state: state => state.user
// Flow: UI → dispatch(action) → reducer → new state → UI re-renders
dispatch({ type: 'counter/increment', payload: 1 });
Q2 Redux Toolkit, createSlice, createAsyncThunk, Middleware, Thunk, Saga? Medium +

Redux Toolkit (RTK): Official, recommended way to write Redux. Reduces boilerplate significantly.

// createSlice – auto-generates actions and reducer
const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: state => { state.value += 1; }, // Immer under the hood
    decrement: state => { state.value -= 1; },
  }
});
export const { increment, decrement } = counterSlice.actions;

// createAsyncThunk – for async actions
const fetchUser = createAsyncThunk('user/fetch', async (id) => {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
});

Middleware: Sits between dispatch and reducer. Use cases: logging, async operations, crash reporting.

Redux Thunk: Allows dispatching functions (for async). Simple, included in RTK.

Redux Saga: Uses generator functions for complex async flows (race conditions, cancellation). More powerful but complex.

Performance Optimization

Q1 Performance Optimization Techniques – Complete Guide Medium +

Preventing unnecessary re-renders:

  • React.memo – memoize component (skips re-render if props unchanged)
  • useMemo – memoize expensive computations
  • useCallback – memoize callback functions passed as props

Bundle size reduction:

  • Code Splitting – split bundle into chunks loaded on demand
  • Lazy Loading – React.lazy() + Suspense for components/routes
  • Tree Shaking – removes unused exports (Webpack/Rollup do this automatically with ES modules)

Large lists:

  • Virtualization – only render visible items (react-window, react-virtual)
  • Pagination – load fixed number of items
  • Infinite Scroll – load more on scroll
// react-window example
import { FixedSizeList } from 'react-window';
<FixedSizeList height={400} itemCount={10000} itemSize={35}>
  {({ index, style }) => <div style={style}>Item {index}</div>}
</FixedSizeList>
Use React DevTools Profiler to identify which components are slow and why before optimizing prematurely.

Q1 API Calls, Axios vs Fetch, JWT, Refresh Tokens, RBAC, Interceptors? Medium +

Axios vs Fetch:

AxiosFetch
JSON auto-parse✅Manual .json()
Request cancellation✅ Built-inAbortController
Interceptors✅Manual wrapper
Error on 4xx/5xx✅ Auto❌ Must check ok
Bundle size~14kbNative (0kb)
// Axios interceptor for JWT + refresh token
axios.interceptors.request.use(config => {
  config.headers.Authorization = `Bearer ${getToken()}`;
  return config;
});
axios.interceptors.response.use(null, async error => {
  if (error.response.status === 401) {
    const newToken = await refreshAccessToken();
    error.config.headers.Authorization = `Bearer ${newToken}`;
    return axios(error.config); // retry
  }
});

JWT Flow: Login → server returns access token (short-lived) + refresh token (long-lived) → store access token in memory, refresh token in httpOnly cookie → auto-refresh when access token expires.

RBAC (Role-Based Access Control): Decode JWT, check user role, conditionally render UI and protect routes.

const PrivateRoute = ({ roles, children }) => {
  const { user } = useAuth();
  if (!roles.includes(user.role)) return <Unauthorized />;
  return children;
};

function Counter() {

}

// ── Custom useDebounce Hook ──
function useDebounce(value, delay = 500) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);
  return debounced;
}
// Usage: const debouncedSearch = useDebounce(searchTerm, 300);

// ── Custom useFetch Hook ──
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);
  useEffect(() => {
    const controller = new AbortController();
    fetch(url, { signal: controller.signal })
      .then(r => r.json())
      .then(setData)
      .catch(e => { if (e.name !== 'AbortError') setError(e); })
      .finally(() => setLoading(false));
    return () => controller.abort();
  }, [url]);
  return { data, loading, error };
}
Q2 Pagination, Infinite Scroll, Accordion, Modal, Tabs Medium + 
// ── Pagination ──
function Pagination({ total, perPage, current, onPageChange }) {
  const pages = Math.ceil(total / perPage);
  return Array.from({ length: pages }, (_, i) => (
    <button key={i+1} onClick={() => onPageChange(i+1)}
      disabled={current === i+1}>{i+1}</button>
  ));
}

// ── Infinite Scroll (IntersectionObserver) ──
function InfiniteList() {
  const [items, setItems] = useState([]);
  const sentinel = useRef();
  useEffect(() => {
    const obs = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting) fetchMore().then(more =>
        setItems(prev => [...prev, ...more])
      );
    });
    obs.observe(sentinel.current);
    return () => obs.disconnect();
  }, []);
  return (<div>{items.map(i => <Item key={i.id} {...i}/>)}<div ref={sentinel}/></div>);
}

// ── Accordion ──
function Accordion({ items }) {
  const [open, setOpen] = useState(null);
  return items.map((item, i) => (
    <div key={i}>
      <button onClick={() => setOpen(open === i ? null : i)}>{item.title}</button>
      {open === i && <div>{item.content}</div>}
    </div>
  ));
}

// ── Modal ──
function Modal({ isOpen, onClose, children }) {
  if (!isOpen) return null;
  return ReactDOM.createPortal(
    <div className="overlay" onClick={onClose}>
      <div className="modal" onClick={e => e.stopPropagation()}>
        {children}
        <button onClick={onClose}>×</button>
      </div>
    </div>,
    document.body
  );
}

React Output Questions

Q1 React Tricky Behaviors: Batching, Memoization, Strict Mode, Context Hard + 
// ── useState Batching (React 18) ──
// Multiple setStates in same event handler → ONE re-render
const handleClick = () => {
  setA(1);
  setB(2);
  setC(3); // Only 1 re-render in React 18 (batched automatically)
};

// ── useEffect dependency pitfall ──
const [count, setCount] = useState(0);
useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1); // ❌ stale closure, always adds 1 to initial value
    setCount(c => c + 1); // ✅ functional update, always correct
  }, 1000);
  return () => clearInterval(id);
}, []);

// ── React.memo doesn't help with object props ──
const Child = React.memo(({ style }) => <div style={style}>...</div>);
// ❌ re-renders every time because {color:'red'} is new object each render
<Child style={{ color: 'red' }} />
// ✅ Fix: useMemo or move object outside component

// ── Strict Mode double-invocation ──
// React.StrictMode calls render + effects TWICE in dev
// to detect side effects. Normal in development, not production.

// ── Context update ──
// ALL consumers re-render when context value changes
// even if their slice of data didn't change
// Fix: split contexts or use useMemo on context value
const value = useMemo(() => ({ user, setUser }), [user]);

Q2 Why Redux? Why not Context API? How do you share state? Medium +

Use Redux when:

  • Complex state with many actions (shopping cart, dashboards)
  • Need time-travel debugging / Redux DevTools
  • Multiple components far apart need same state
  • Complex async workflows (Saga/Thunk)

Use Context API when:

  • Simple, low-frequency updates (theme, locale, auth status)
  • Small to medium apps
  • Want to avoid extra dependencies

Modern alternatives: Zustand, Jotai, Recoil (simpler than Redux), TanStack Query (server state).

Q3 API Layer, Failures, Deduplication, JWT Flow, Protected Routes? Medium +

API Layer best practices:

  • Centralize axios instance with base URL and interceptors
  • Use TanStack Query to avoid duplicate requests (request deduplication built-in)
  • Handle errors globally with interceptors + local error boundaries
// Centralized axios instance
const api = axios.create({ baseURL: process.env.REACT_APP_API_URL });
api.interceptors.request.use(addAuthToken);
api.interceptors.response.use(null, handleError);

JWT Best Practices: Store access token in memory (not localStorage), refresh token in httpOnly cookie, auto-refresh before expiry.

Q4 Performance, Scalability, Large Lists, 100k Users, Onboarding? Hard +

  • Virtualized lists (react-window) for 10k+ item tables
  • React.memo + useCallback for heavy child components

  • TanStack Query for caching API responses (no duplicate calls)

Scaling to 100k users:

  • CDN for static assets (Cloudfront, Vercel Edge)

  • API Gateway + Load balancer on backend

Onboarding developers: README with setup steps, ADRs (Architecture Decision Records), Storybook for components, consistent ESLint/Prettier config, PR templates.

Q6 Most Difficult Bug? Biggest Challenge? What Would You Improve? Medium +

Framework for answering (STAR method):

  • Situation: Set the context (what were you building?)
  • Task: What was the specific problem/requirement?
  • Action: How did you debug/approach it? What tools did you use?
  • Result: What was the outcome? What did you learn?

Example answer for "Difficult Bug": "We had a memory leak in production where the app's memory kept growing after navigation. I used Chrome DevTools heap snapshots to find that our useEffect subscriptions weren't being cleaned up in a custom hook used across 15 components. Added the cleanup return function and memory stabilized. This led us to add a team convention: always review useEffect cleanup in PRs."

What would you improve? Be honest and forward-thinking: "I'd add more integration tests — we caught a production bug that our unit tests missed. I'd also introduce TanStack Query to replace our custom data-fetching hooks and get caching/deduplication for free."
